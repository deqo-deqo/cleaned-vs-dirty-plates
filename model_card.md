# Model Card: Cleaned vs Dirty Plates

Дата актуализации: 19 октября 2026 года.

Документ организован по разделам Google Model Cards: сведения о модели, назначение, факторы качества, метрики, данные, количественный анализ, этические аспекты и рекомендации. Основа — [Model Cards for Model Reporting](https://research.google/pubs/model-cards-for-model-reporting/).

## 1. Сведения о модели (Model Details)

| Поле | Значение |
| --- | --- |
| Проект | [cleaned-vs-dirty-plates](https://github.com/deqo-deqo/cleaned-vs-dirty-plates) |
| Автор проекта | Дмитрий Хоменко; владелец репозитория `deqo-deqo` |
| Проверенная версия кода | `d395e1dda9af8d7dca3aaa27f4dfc21626b64f41` |
| Задача | Бинарная классификация изображения тарелки по наличию видимого загрязнения |
| Архитектура | `torchvision.models.mobilenet_v3_small`; последний линейный слой заменён на слой с двумя выходами |
| Фреймворк | PyTorch / torchvision |
| Инициализация | По умолчанию предобученные веса ImageNet; доступен режим `--weights none` |
| Дообучение | Градиенты разрешены для последнего блока `features[-1]` и всего `classifier`; остальные параметры заморожены |
| Статус | Учебный прототип для изучения ML и MLOps, без подтверждённого производственного внедрения |
| Артефакт модели | Скрипт держит веса моделей фолдов в памяти во время выполнения; отдельная версия весов на диск не сохраняется |
| Лицензирование | Условия использования кода, датасета и предобученных весов необходимо проверить отдельно перед распространением; наличие публичного репозитория само по себе не задаёт лицензию |

В коде предусмотрен переход к случайной инициализации, если загрузка ImageNet-весов не удалась. Поэтому `--weights imagenet` сам по себе не доказывает, что конкретный запуск использовал предобученные веса. Для сопровождаемого процесса нужно сохранять фактический источник весов и прекращать такой запуск при неожиданной ошибке загрузки.

### Вход и выход

- Вход текущего скрипта: архив `plates.zip` с JPEG-файлами в `plates/train/dirty/`, `plates/train/cleaned/` и `plates/test/`, а также CSV-шаблон `sample_submission.csv`.
- Вход нейронной сети: RGB-тензор формы `[N, 3, 160, 160]` при настройках по умолчанию.
- Выход сети: два логита. После softmax получаются оценки вероятностей классов в порядке `dirty = 0`, `cleaned = 1`.
- Для каждого изображения усредняются вероятности по трём вариантам TTA: оригинал, горизонтальное и вертикальное отражения. Для тестовых изображений дополнительно усредняются результаты моделей фолдов.
- Итоговый класс определяется через `argmax`. В `submission.csv` сохраняются столбцы `id,label`; идентификаторы дополняются нулями слева до четырёх символов. Вероятности в этот CSV не записываются.

Оценки softmax не откалиброваны и не являются гарантией правильности результата. Модель классифицирует изображение целиком: рамки объектов, сегментацию загрязнений и подсчёт тарелок она не выдаёт.

## 2. Назначение (Intended Use)

**Основное применение:** учебный проект, на котором демонстрируются воспроизводимое обучение, оценка качества и проектирование сопровождения модели.

**Предполагаемый прикладной сценарий:** помощник визуальной проверки тарелок после мойки. Модель предлагает класс, сотрудник проверяет тарелку и принимает окончательное решение. Этот сценарий спроектирован в [Model_BPMN.md](Model_BPMN.md), но ещё не внедрён.

**Пользователи:** разработчик ML/MLOps-проекта; в предполагаемом сценарии — сотрудник, проверяющий результат мойки.

Модель не предназначена для самостоятельного допуска посуды к использованию, определения микробиологической безопасности, работы с произвольными объектами или оценки фотографии с несколькими тарелками. Метка `cleaned` означает визуальный класс датасета, а не санитарное заключение.

## 3. Факторы качества (Factors)

Ожидаемые факторы ошибок: освещение, тени и блики; ракурс и масштаб; цвет и рисунок посуды; фон; размер и тип остатков еды; смазанные изображения и частичное перекрытие тарелки.

В репозитории нет количественных срезов качества по камерам, условиям освещения или типам посуды. Поэтому нельзя утверждать устойчивость модели к этим факторам. При сборе новых данных следует сохранять такие признаки и проверять качество по срезам. Демографические категории к целевой задаче не относятся; людей и личные данные в кадре желательно исключать.

## 4. Метрики (Metrics)

| Метрика | Назначение |
| --- | --- |
| Accuracy | Доля правильных ответов; используется для выбора лучшей эпохи внутри фолда |
| Precision для каждого класса | Доля верных ответов среди предсказаний данного класса |
| Recall для каждого класса | Доля найденных объектов данного класса среди всех объектов этого класса |
| Macro F1 | Среднее F1 двух классов; учитывает качество обоих классов |
| Матрица ошибок | Показывает направления ошибок `dirty → cleaned` и `cleaned → dirty` |

В предполагаемом процессе особенно важен **recall класса `dirty`**: ошибка `dirty → cleaned` означает пропуск визуального загрязнения. В этой интерпретации положительным классом считается `dirty`, хотя в коде он имеет индекс 0; метрики нужно вычислять с явным указанием класса.

Калибровка вероятностей, время ответа и потребление ресурсов количественно не оценены в этой карточке. Пороговые требования к будущим кандидатам описаны отдельно в [Model_retrain_BPMN.md](Model_retrain_BPMN.md); это предлагаемые условия допуска, а не достигнутые результаты.

## 5. Данные оценки (Evaluation Data)

По существующему README и отчёту размеченная выборка содержит **40 изображений: 20 `dirty` и 20 `cleaned`**. Используется `StratifiedKFold` с тремя фолдами, перемешиванием и `seed=42` по умолчанию. Для каждого изображения формируется out-of-fold (OOF) предсказание моделью, не обучавшейся на нём градиентным методом.

Однако тот же валидационный фолд используется для выбора лучшей эпохи и early stopping. Поэтому OOF-результат не является независимой финальной тестовой оценкой и может быть оптимистичным. Отдельная размеченная отложенная выборка в текущем процессе не предусмотрена.

OOF оценивает модели отдельных фолдов, тогда как итоговый CSV использует их ансамбль. Качество именно этого ансамбля на независимом размеченном тесте не измерено.

В отчёте указано **744 тестовых изображения без доступных проекту меток**. Они используются для создания Kaggle submission, но не позволяют самостоятельно вычислить метрики качества. Результат на лидерборде здесь не заявляется.

При оценке выполняются RGB-конвертация, `SquarePad` с заполнением средним цветом, `Resize(int(image_size * 1.12))`, `CenterCrop(image_size)`, преобразование в тензор и нормализация ImageNet. По умолчанию размер — 160 × 160, mean — `(0.485, 0.456, 0.406)`, std — `(0.229, 0.224, 0.225)`. Применяется TTA.

## 6. Данные и процедура обучения (Training Data)

Источник — соревнование Kaggle **Cleaned vs Dirty V2**, предоставленное проекту в архиве. Метка определяется именем каталога. Детальный способ сбора исходных фотографий, процедура разметки, лицензия и независимость объектов съёмки в документации проекта не установлены. Изображения датасета в рамках подготовки этой карточки заново не проверялись.

Обучающая часть каждого фолда получает `SquarePad`, `RandomResizedCrop(scale=(0.72, 1.0), ratio=(0.9, 1.1))`, случайные отражения, повороты до 22 градусов, `ColorJitter` и нормализацию ImageNet. Аугментации не создают новые независимые наблюдения и не увеличивают фактический объём размеченной выборки.

| Параметр | Значение по умолчанию в коде |
| --- | --- |
| Фолды / seed | 3 / 42 |
| Максимум эпох / patience | 6 / 3 |
| Batch size / размер | 16 / 160 × 160 |
| Оптимизатор | AdamW |
| Learning rate classifier / последнего блока | `3e-4` / `5e-5` |
| Weight decay | `1e-4` |
| Функция потерь | CrossEntropyLoss, label smoothing `0.05` |
| Устройство | CUDA, иначе MPS, иначе CPU |

В историческом отчёте указан запуск на 10 эпох, в актуальном CLI значение по умолчанию — 6. Это разные конфигурации; их не следует смешивать при сравнении запусков. Фиксация seed помогает воспроизводимости, но не гарантирует побитового совпадения между устройствами и версиями библиотек.

## 7. Количественный анализ (Quantitative Analyses)

Следующие числа **перенесены из существующих README и отчёта**, а не получены новым запуском. В репозитории нет полного набора артефактов запуска, связывающего эти числа с конкретными весами, конфигурацией и версией данных; повторное получение тех же значений на актуальном коде не подтверждено.

| Класс | Precision | Recall | F1 | Число изображений |
| --- | --- | --- | --- | --- |
| dirty | 0.800 | 0.400 | 0.533 | 20 |
| cleaned | 0.600 | 0.900 | 0.720 | 20 |
| Macro average | 0.700 | 0.650 | 0.627 | 40 |

OOF accuracy в отчёте — **0.650 (26 из 40)**. Простое среднее accuracy трёх фолдов — **65.02%**, стандартное отклонение по фолдам — **3.18 процентного пункта**. Среднее по фолдам и accuracy по всем изображениям слегка различаются из-за разных размеров фолдов.

Матрица ошибок из отчёта (строки — истинные классы, столбцы — предсказанные):

| Истинный класс | Предсказано dirty | Предсказано cleaned |
| --- | --- | --- |
| dirty | 8 | 12 |
| cleaned | 2 | 18 |

Из 20 грязных тарелок пропущено 12. Это ключевое ограничение для предполагаемого применения. При сбалансированных классах постоянный ответ даёт accuracy 50%, но превышение этого ориентира на 40 изображениях ещё не доказывает готовность к эксплуатации. Доверительные интервалы и независимая проверка на реальных условиях не представлены.

## 8. Этические аспекты (Ethical Considerations)

Ошибка модели может привести к повторной мойке чистой тарелки или пропуску видимого загрязнения. Поэтому в предлагаемом сценарии решение остаётся за человеком. Нельзя представлять предсказание как подтверждение безопасности посуды.

Для будущего сбора фотографий нужны понятные права использования, исключение людей и персональных данных из кадров, а также проверка разметки человеком. Предсказания модели не должны автоматически становиться истинными метками для переобучения: это закрепляло бы её ошибки.

## 9. Ограничения и рекомендации (Caveats and Recommendations)

1. Текущая модель пригодна для учебных экспериментов; её качество недостаточно для самостоятельного производственного контроля.
2. Нужны дополнительные независимые фотографии обоих классов и отдельный размеченный holdout, не используемый для early stopping или подбора параметров. Снимки одной тарелки/сессии нужно держать в одном разделе данных.
3. Необходимо регистрировать фактическую инициализацию, версии данных и кода, параметры, окружение, веса всех моделей фолдов, порядок классов и предобработку.
4. Перед применением необходимо проверить качество на целевых камерах и условиях, время обработки и воспроизводимость загрузки артефакта.
5. Сохранение версий, автоматическое переобучение, деплой, мониторинг и откат пока описаны как проектируемый процесс, а не реализованные функции репозитория.
